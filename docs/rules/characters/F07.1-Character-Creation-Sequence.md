# F07 — Character Creation
## F07.1 — Character Creation Sequence

**Document status:** Foundation draft  
**System:** Blackbox Protocol  
**Dependencies:** F01–F06

### 7.1.1 Purpose

Character creation establishes a mechanically valid, narratively coherent character whose abilities reflect their background, education, occupational experience and personal development.

The process must produce characters with distinct capabilities and limitations rather than interchangeable combinations of numerical bonuses. Professional experience establishes a foundation of competence but does not guarantee proficiency outside the character's documented experience.

All character creation mechanics must conform to the established foundation rules.

### 7.1.2 Character Creation Stages

| Stage | Description | Required output |
|---|---|---|
| 01 | Campaign configuration | Applicable campaign rules and restrictions |
| 02 | Character concept | Identity, background and intended role |
| 03 | Attribute allocation | Valid starting attributes |
| 04 | Occupational selection | Occupation and qualification record |
| 05 | Occupational grants | Granted skills, competencies and specializations |
| 06 | Personal skill allocation | Additional skills and alternative selections |
| 07 | Competency development | Additional eligible competencies |
| 08 | Specialization selection | Qualified specialized applications |
| 09 | Personal history | Education, experience and relationships |
| 10 | Occupational advantages | Verified occupational benefits |
| 11 | Derived statistics | Calculated character statistics |
| 12 | Starting resources | Equipment, possessions and available resources |
| 13 | Character validation | Validated character record |
| 14 | Character finalization | Playable character sheet |

### 7.1.3 Campaign Configuration

Before allocating character resources, the applicable campaign parameters must be established.

Campaign configuration determines the permitted character creation options, occupational availability, starting resource restrictions, environmental conditions and any authorized deviations from standard creation rules.

Campaign restrictions must be established before character creation begins. Exceptions must be documented and approved by the Game Master.

Campaign configuration must not silently override foundation mechanics.

### 7.1.4 Character Concept

The player establishes the character's intended identity and background.

The character concept should address:

- Personal identity and age.
- Educational background.
- Previous occupation.
- Relevant professional experience.
- Personal interests and motivations.
- Relationships and responsibilities.
- Intended role within the campaign.
- Significant limitations or circumstances.

Narrative descriptions do not independently grant mechanical benefits. Any mechanical benefit associated with a character's history must originate from an authorized creation rule.

### 7.1.5 Attribute Allocation

Starting attributes must be allocated according to the established attribute generation rules.

All attribute values must remain within permitted starting limits. Attribute expenditures, adjustments and exceptions must be recorded.

Attribute allocation must be completed before finalizing any selection dependent upon attribute prerequisites.

Changes to attributes require revalidation of all affected skills, competencies, specializations and derived statistics.

### 7.1.6 Occupational Selection

The player selects an occupation from the canonical occupation database.

The selected occupation establishes the character's professional foundation, including applicable qualifications, skill grants, competency grants, specialization opportunities and occupational advantages.

Occupational selection does not automatically establish current employment, institutional authority, professional licensing, equipment ownership or access to restricted resources.

Additional occupations or professional backgrounds may only be selected where expressly permitted by established creation rules.

### 7.1.7 Occupational Grant Application

All mandatory occupational grants must be applied before discretionary character development.

Each grant must retain its originating occupation identifier and applicable rule reference.

Where multiple grants affect the same skill, competency or specialization, the established stacking and duplicate-grant rules determine the resulting value.

Unused, duplicated or ineligible grants must not automatically convert into discretionary points unless an established rule explicitly permits conversion.

### 7.1.8 Personal Skill Allocation

Following occupational grant application, the player may allocate available discretionary skill resources.

Personal skill selections represent education, hobbies, secondary experience and other development outside the character's primary occupation.

All selections must satisfy applicable prerequisites, starting proficiency limits and allocation costs.

Alternative occupational skill selections must originate from the permitted options associated with the selected occupation.

### 7.1.9 Competency Development

Competencies represent demonstrated capability within defined practical applications.

Competency selection must distinguish between theoretical knowledge, practical experience and verified proficiency.

Characters must satisfy applicable skill prerequisites, training requirements, qualification requirements and starting competency restrictions.

A character's occupational title alone does not establish competence in every activity associated with that profession.

### 7.1.10 Specialization Selection

Specializations represent focused development within an established skill or competency.

Specializations may only be selected when the character satisfies the associated eligibility requirements.

Specialization benefits apply exclusively within their defined application scope.

A specialization must not independently grant unrelated competencies, unrestricted professional authority or broader proficiency than permitted by its governing rules.

### 7.1.11 Personal History and Occupational Advantages

The character's personal history establishes the narrative circumstances supporting their professional and personal development.

Occupational advantages must be individually documented and verified where required.

Contacts, professional relationships, references and institutional associations must reflect campaign conditions and actual availability.

An advantage must not provide an automatic mechanical modifier unless the governing rules explicitly establish one.

### 7.1.12 Derived Statistics

Derived statistics must be calculated using the canonical formulas established within the foundation rules.

Derived values must not be independently assigned or manually increased without an authorized adjustment.

Every derived statistic must retain sufficient calculation information to permit verification.

Changes to contributing attributes, skills or other mechanical values must trigger recalculation.

### 7.1.13 Starting Resources

Starting resources must be assigned according to established equipment, economic and campaign rules.

Resource allocation must distinguish between:

- Personal ownership.
- Borrowed equipment.
- Institutional access.
- Shared resources.
- Consumable supplies.
- Restricted or unavailable equipment.

Professional experience does not automatically establish possession of professional equipment.

All starting resources must comply with applicable campaign restrictions and resource allocation limits.

### 7.1.14 Character Validation

Before finalization, every character must undergo mechanical and semantic validation.

Validation must identify:

- Invalid attribute values.
- Exceeded allocation limits.
- Missing prerequisites.
- Invalid occupational selections.
- Unauthorized grants.
- Duplicate grant conflicts.
- Invalid skill or competency identifiers.
- Ineligible specializations.
- Incorrect derived statistics.
- Unauthorized starting resources.
- Unsupported occupational advantages.
- Contradictory qualification records.

Validation findings must be classified as errors, warnings or informational notices.

Errors prevent finalization. Warnings require review and resolution or an explicitly authorized exception. Informational notices do not prevent finalization.

### 7.1.15 Dependency Management

Character creation must support revision of earlier decisions without corrupting dependent selections.

| Changed selection | Required revalidation |
|---|---|
| Campaign configuration | Entire character |
| Attributes | Prerequisites and derived statistics |
| Occupation | Occupational grants, alternatives and advantages |
| Skill selection | Dependent competencies and specializations |
| Competency selection | Dependent specialized applications |
| Personal history | Qualifications and narrative advantages |
| Starting resources | Resource limits and availability |

Invalidated selections must be identified explicitly rather than silently removed or replaced.

Any resulting point refunds or resource adjustments must follow established rules.

### 7.1.16 Character Finalization

A character may be finalized only when all mandatory creation stages have been completed and no unresolved validation errors remain.

The finalized character record must contain:

- Character identity and personal history.
- Applicable campaign configuration.
- Attribute values.
- Occupational selections and qualifications.
- Skills and proficiency values.
- Competencies and specializations.
- Occupational advantages.
- Derived statistics.
- Starting resources.
- Authorized exceptions.
- Validation results.
- Applicable ruleset version.

Finalization establishes the character's starting mechanical state. Subsequent development must follow the established advancement system.

### 7.1.17 Acceptance Criteria

The character creation sequence is considered complete when it:

1. Provides an unambiguous creation order.
2. Integrates the established foundation systems.
3. Preserves canonical mechanical rules.
4. Prevents unauthorized or duplicate grants.
5. Supports dependency-aware character revision.
6. Produces mechanically valid character records.
7. Supports both manual and digital character creation.
8. Establishes a consistent starting state for subsequent advancement.
