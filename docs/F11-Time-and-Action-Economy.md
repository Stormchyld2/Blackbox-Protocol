# F11 — Time and Action Economy

Canonical sources: DESIGN-NOTES.md F02, F11, Section 3 derived movement, Section 4 encounter/recovery, CCDD-12 and F10. This is a delegated working implementation reference; no numerical rule changes.

## 1. Shared clock
One authoritative in-world calendar and elapsed clock per campaign. Record epoch/date, current instant, elapsed duration, event history and scheduled events. Use integer seconds internally as a proposed implementation convention; tabletop may use calendar and elapsed blocks. Calendar months follow campaign calendar, not fixed 30-day substitutes; F10 separately requires at least30 days for attribute development. Real-world discussion, session gaps and application wall clock do not advance fiction automatically. GM authorizes advancement, players declare actions. Historical corrections are audited, not ordinary backward time travel.

## 2. Scales and transitions
Scene: seconds/minutes or declared duration. Encounter: six-second rounds. Travel: actual elapsed minutes/hours/days, F19 owns speed and exertion. Downtime: hours/days, F10 owns learning credit. Projects: days/weeks/months, F21/F22 own production. World: seasons/years, F24 owns scheduled changes. Switching scale preserves clock, unfinished actions, resources and deadlines. No rounding each short interval into a whole hour. One hour=3600 seconds, day=86400 seconds for elapsed-time accounting; calendar representation can vary by setting.

## 3. Resolution procedure
Establish stakes, scale and feasible intent; declare duration and required resources before uncertainty; resolve using existing dice; advance elapsed clock to next meaningful boundary; apply due events, consequences and resource changes once; record outcome and remaining work. Routine actions need no roll; impossible actions cannot be made possible by spending time alone. Failed actions consume declared elapsed time unless fiction establishes an earlier interruption. No repeated rolls without changed circumstances. Pause at deadlines or events that can alter decisions; simultaneous events at same instant are adjudicated together by GM, stable IDs prevent duplicate processing. Events scheduled at current instant resolve before further advancement. Event order and interruptions are delegated procedural defaults.

## 4. Encounter action economy
Six seconds per round, not six seconds per participant. Initiative descending derived floor((DEX+PER)/2), ties higher effective PER, then simultaneous declared actions with GM adjudication if incompatible. Recalculate next round. One main action, one movement allowance, one reaction per round; main may convert to second movement, never extra reaction. Brief feasible speech/drop incidental; no unlimited free actions, banking or extra round for surprise. Awareness limits reactions. Walk allowance max(1,floor(M/5)) metres for mobile character, zero if unable, M=floor((STR+DEX+CON)/3). F12 owns attack/defense and other encounter effects. At encounter exit, advance actual completed round intervals once; partial-round exit convention: count the started round as six seconds unless GM records a shorter actual elapsed interval, never charge both. No automatic movement or actions from unused allowances.

## 5. Concurrent activity and interruptions
Record participant, start/end, activity, resource reservations, progress, outcome and status. Independent actors can work simultaneously; elapsed clock advances by union of concurrent intervals, not sum. Same actor cannot allocate overlapping exclusive active work. Passive processes may run alongside active work if resources and supervision allow; passive time is not active learning credit. Shared resources cannot exceed available capacity. Interruptions stop active credit at boundary; retain eligible completed progress, reevaluate prerequisites and resume with remaining work. Example: two characters research and repair from 09:00–11:00; campaign advances two hours, each receives at most two hours eligible activity. A 10:00 meeting interrupts only attendees, not unrelated work.

## 6. Downtime and training
Available active time is elapsed interval minus sleep, duties, travel, recovery and other exclusive commitments. No universal daily training entitlement. F10 ledger allocates each time entry once; CCDD slots do not generate hours. Credit capped at target hours, excess does not automatically roll forward. Assessment pending is not acquired competency. General practice marks per distinct40 active hours; adaptation normally8 active hours plus demonstration; no real-time advancement. Recovery and learning may coexist only where fiction permits, never double credit incompatible activities. F13/F14 own recovery rates; eight-hour sleep replaces hourly stamina/stress recovery for same interval, not an additional award. Different independent recovery pools may update from same eligible rest interval under their own rules.

## 7. Modes
Standard: calendar, meaningful blocks, essential deadlines, abstract encounter positions. Advanced: individual schedules, interruptions, resource reservations and precise elapsed hours. Simulation: detailed event and resource ledger, optional fine-grained schedules. Same action budgets, eligibility and outcomes; detail does not create extra rewards. GM can change detail at a scene boundary without resetting clock or progress.

## 8. Printable and digital records
Calendar: campaign/date/time, event ID, due time, visibility, status, consequence. Encounter tracker: round, initiative/PER, main/movement/reaction spent, awareness, elapsed. Downtime sheet: participant, interval, exclusive/passive, project, resource, credited time, evidence, interruption. Project sheet: F10 schema, remaining work, dependencies, assessment. Digital implementation must use canonical time, idempotent event/outcome IDs, audited corrections, no wall-clock auto-credit; F31–35 own architecture and sync.

## 9. Acceptance
Reference tests cover elapsed rounds, action budgets, movement bounds, parallel intervals, exclusive overlap, event boundaries and duplicate event processing. F12–14 and F19–24 retain domain mechanics. Actual campaign pacing, action balance, interruption burden and software integration require F36 and implementation. No real-world tactical rules introduced.
